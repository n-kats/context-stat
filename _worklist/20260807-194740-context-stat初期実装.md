## 実装範囲

- MCP SDKは標準依存とし、`[mcp]` extraは作らない。
- MCPの計測対象は論理的な`generated`と`returned`とする。JSON-RPC envelopeなどのwire-level計測は実装しない。
- MCPの`tools/list`、`resources/list`、`prompts/list`、`tools/call`、`resources/read`、`prompts/get`を対象候補とする。SDKの未対応操作は明示的にエラーにする。
- tiktokenは標準依存として導入し、`auto`の明示的な解決先にする。tokenizersとAnthropic APIはextraで追加する。
- 画像は形式・容量・寸法を計測する。正式な画像トークン式が登録されていないモデルは`unsupported`とする。任意のリサイズは行わない。
- `--command`はJinjaレンダリング後にargv化し、`subprocess`の`shell=False`で実行する。
- MCP一覧は`mcp list --config`、リクエストは`mcp request --config --method --name --params`で実行する。
- Gitの`--`区切りはClickのオプション解析で失われないように保持してから専用パーサーへ渡す。
- 直接指定された画像は`--include-images`なしでも対象にし、ディレクトリ再帰時の画像は`--include-images`で明示する。
- `--backend`を省略した場合は`auto`とし、`auto`は`tiktoken`を明示的に選択する。

## 実施結果

- `uv sync --extra dev`で開発依存を解決した。
- `uv run pytest`で16件のテストが通過した。
- `uv run ruff check .`と`uv run ruff format --check .`が通過した。
- `uv tool install .`は実行環境の`/home/ubuntu/.local`が読み取り専用のため失敗した。同じuvのインストール処理を、ツール環境と実行ファイルの配置先を`/workspace/_tmp`へ指定して成功させた。
- 公式MCP Python SDKのlow-level stdioサーバーを実機起動し、`mcp list`と`mcp request`で接続、一覧、tools/call、送受信計測を確認した。
- `uv run`で標準依存のtiktokenによるGPT系計測を確認した。

## 実装上の留保

- GPT-5.6系はOpenAI公式のモデルガイドでモデルIDとファミリーを確認した。tiktoken公式のモデル表はGPT-5を`o200k_base`へ対応付けているが、GPT-5.6の直接エントリはないため、GPT-5.6系の`o200k_base`選択は推論に基づく`estimated`として実装した。
- 初期実装時点ではClaude 5系のローカル画像式を候補ポリシーとして扱った。その後、正式IDごとのモデルプロファイル、公式上限、標準・高解像度層を確認し、コードとテストへ反映した。
- Anthropic APIの画像計測は`--backend anthropic-api --allow-online`を明示した場合だけ実行する。外部送信しないローカル計測とは別経路にする。
